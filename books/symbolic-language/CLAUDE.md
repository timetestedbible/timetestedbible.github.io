# MEAT — The Bible's Symbolic Language: agent orientation

Book by Daniel Larimer, print via BookBaby (hardcover, ISBN 978-1-7365211-6-8) + web at
timetested.bible (this repo IS the deployment — GitHub Pages serves it directly).

## Layout

- `NN-*.adoc` — chapters. Front matter: `title`, `slug`, `permalink`, `order` (drives
  assembly order — NOT the filename), `description`, `epigraphs`. Bonus chapters carry
  `edition: digital` (wrapped `ifndef::print-edition[]` in the print build). `NNx-*.adoc`
  are order-N.5 inserts; edition comes from front matter, not the x (16x/41x digital-only,
  38x print-only, 46x both editions — author's ruling 2026-07-12).
- `48-glossary.adoc` — the symbol glossary. Entry format:
  `[[sym-anchor]]Term (qualifier) verdict:divergent[]:: definition +` then optional
  `[.commonview]__Commonly taught: …__ +` then `[.seeref]__(verses) · see link:…[Chapter Title][.chnum]#, ch. N#__`.
  Badges (DIVERGENT / NOVEL) come from the blind test; the preamble states the entry count — keep it true.
- `print/build.rb` — assembles and renders the trade PDF (asciidoctor-pdf + `print/extension.rb`).
  `PARTS` map in build.rb assigns part titles by slug. Citations are abbreviated at build time
  (write full book names in source). `[.chnum]#…#` spans are stripped for print, kept on web.
- `research/` — one `research-<topic>.md` per study; the glossary and chapters cite these.
- `images/masters/` (source), `images/print/` (tone-curved for uncoated stock via
  `print/plate-print-tone.py`), `images/ebook/` (generated, gitignored).
- Repo root: `bibles/` (texts), `data/hg-chapters/` (Hebrew Gospels interlinear JSON),
  `_symbols/`, `_verses/`, `words/` (site studies), `scripts/` (data builders).

## Building the print PDF

```sh
./books/symbolic-language/print/build.rb setup      # first checkout only
cd books/symbolic-language/print && ./build.rb
mdls -name kMDItemNumberOfPages the-bibles-symbolic-language-print.pdf   # page count (target ~480)
```

The executable build script automatically leaves macOS's obsolete system Ruby
for Homebrew Ruby. `ruby build.rb` is also safe: the script performs the same
restart before loading Bundler or Asciidoctor.

Discipline (hard-won — violating this has silently destroyed edits):

1. **ONE build at a time, ever.** Edits in the foreground first (verify each by grep-back),
   then a single background build. If new edits arrive mid-build, KILL the build first
   (stop the whole shell, not just ruby), edit, relaunch.
2. **Never chain `git commit` after the build command.** The pipe eats ruby's exit status,
   so the commit fires even on failure, and killing the build leaves git commands queued.
   Build → verify output (page count + pdftotext greps for the edited phrases) → commit
   as a separate step → confirm the hash in `git log`.
3. Footnotes render in a multi-pass loop; only the final pass draws the notes. A killed
   build can leave a PDF with numbered markers and no notes — that's an artifact, not a bug.
4. The PDF itself is gitignored. `scripture-index.json` is generated by the build but IS
   committed (the live site serves it) — include it in chapter commits.
5. Generated-but-served files must be committed: `bibles/*.gz` and `data/*.json.gz` are what
   the PWA actually fetches. After changing `bibles/*.txt` or `data/*.json`, regenerate with
   `node scripts/build-bible-gz.js` and `node scripts/build-data-gz.js` or the site serves stale data.
6. `git -C <absolute-repo-path>` for all git ops. Never push without the author's explicit say-so.

## How to do a symbol study

1. **Gather every occurrence.** `bibles/kjv_strongs.txt` has inline Strong's tags —
   `grep '{H4522}' bibles/kjv_strongs.txt` finds every verse with that word. Verify
   "same word" claims against the tags before asserting them; thematic links often but
   not always share a lexeme (symbols match by structure, not spelling).
2. **Second witness:** the Hebrew Gospels (`bibles/hg.txt`, `data/hg-chapters/<Book>-<N>.json`
   — fields: `verses[].translation`, `verses[].words[[hebrew, strongs, gloss]]`, notes).
   Versification sometimes runs one verse off the Greek (e.g. Revelation 13).
3. **Consonantal readings are in bounds** — the author studies unpointed Hebrew; a
   consonant-permitted reading can stand against the vowel points. Wordplay is a second
   dimension, flagged as wordplay, never as the definition.
4. **Sweep for counter-texts before fixing a definition** — define the range, not one
   fitted sense. Identity claims need identity-grade evidence.
5. Write it up as `research/research-<topic>.md`: occurrences, the pattern, candidate
   definition, counter-texts weighed, verdict.
6. **Blind grading** (for glossary entries): 3 agents with no repo access state the
   consensus meaning; 3 skeptical graders read the research file and check the citations
   against `kjv_strongs.txt`/HG, output `VERDICT: Match|Refined|Divergent|Novel` — the
   majority verdict becomes the badge, and the glossary counts are updated.

## House style (the rules that get edits rejected)

- **A symbol** = a word whose scriptural meaning ≠ its dictionary meaning. "Kingdom" is a
  meaning (of Mountain), not a symbol. Recovered *words* (belief, truth, gospel…) are a
  distinct class — the meaning was flattened in translation, no image transfer.
- **Quote in context**: scene first, verse full enough to carry the point, conclusion after.
- **No hedging, no meta-talk**: assert the case; never name a debate, never explain the
  chapter's own staging to the reader, never leave verdicts "for the reader to weigh."
- **Ask, don't answer**: forward references pose the puzzle (name the verse and the chapter
  that earns it) — never "will turn out to be X." No sym: links that point at the answer.
- **One-direction handoffs**: a chapter's end may point forward (linked chapter title in
  prose); a chapter never opens by reaching back.
- **Numbers are digits**, even inside quotes (603,550; 144,000; "666 talents"). One-word
  small numbers may stay words.
- **anomia = "lawlessness"** in every quote (KJV "iniquity"); check the Strong's tag —
  2 Tim 2:19 is adikia and keeps "iniquity."
- **Translation choice is per-quote** (KJV/ASV/NKJV — whichever renders the key word
  faithfully), version named in the citation. Never quote-then-correct; a translation
  footnote is a last resort for when no version carries the reading, and it states the
  bare fact only.
- Sentences never start with That/And/But. Paragraphs stay under ~7 sentences — split at
  the evidence→assembly seam, promoting key inline quotes to `[quote.scripture]` blocks.
- In scripture quotes: symbol words get `sym:sym-x[word]` links, meaning-words get `*bold*`.
- Tables use the house style: `.caption` line + `[.prevalence-table%unbreakable, frame=topbot, grid=none, cols="…"]`.
- Real-life anchors (fish on cars, hymn lines) are welcome when they let an identification
  stand without a proof chain.
- The author is law-positive: a symbol deepens a literal command, never dissolves it.
  Argue from Scripture's own cross-text definitions, not common-sense claims.
- TimeTested.Bible is mentioned only in front/back matter or footnotes, never in body prose.
- Check `data/translation-patches.json` before citing a patched verse (e.g. Dan 9:26).

## Verification habits

- After every edit: grep the file for the new phrase (edits have been lost to races before).
- After every build: page count + `pdftotext` + grep for the edited phrases (beware
  hyphen-ation and line wraps breaking exact matches).
- After every commit: confirm the hash appears in `git log`.

## Audio edition (audio/)

`audio/NN-*.adoc` mirrors each print chapter as a narration script — same argument,
rewritten for the ear. Principles in `audio/README.md` (never read chapter:verse;
attribution/recall/scene references instead; [beat]/[pause]/[long pause] markers).
SYNC RULE: when a print chapter changes at the meaning level, update its audio twin
in the same sitting and bump its `synced-to:` hash (drift check:
`git log -1 --format=%h -- <source>` vs the front-matter value). Print is the source
of truth; doctrine edits never originate in audio/.
